# Titan Mapper

**Advanced keyboard / mouse mapping platform for Android**

Titan Mapper lets you remap USB OTG, Bluetooth, and wireless-dongle keyboards and mice
to touch inputs, system actions, macros, and plugins — entirely on-device, with no cloud
dependency. It supports four permission tiers, from fully sandboxed to root-enhanced.

> ⚠️ **Status:** This codebase was generated by Claude and has **not been compiled or run**.
> It is architecture-complete and production-patterned, but will likely require minor fixes
> (import corrections, Compose API version drift) before it builds cleanly. See §Build below.

---

## Permission tier capabilities

| Tier | Capture | Inject | Notes |
|---|---|---|---|
| **Standard** | Activity-scoped key/motion events only | Touch gestures via `UiAutomation` (self only) | Works without any special grants; mapping limited to the focused window |
| **Accessibility** | System-wide keys via `FLAG_REQUEST_FILTER_KEY_EVENTS` | Touch gestures via `AccessibilityService.dispatchGesture` | No key injection; user must enable the Accessibility service manually |
| **Shizuku** | HID events via hidden `InputManager.injectInputEvent` (reflection + HiddenApiBypass) | Key + pointer injection system-wide | Requires Shizuku server running (adb or Sui); survives reboots with Sui |
| **Root** | Raw evdev byte stream from `/dev/input/event*` | `input keyevent` / `input tap` shell commands | Full evdev fidelity; `uinput` virtual device is a planned upgrade (v2) |

## Build instructions

### Prerequisites

- Android Studio Ladybug (2024.2) or later, **or** command-line with JDK 17
- Android SDK 36 (compileSdk), minSdk 31

### Steps

```bash
git clone https://github.com/<owner>/titan-mapper.git
cd titan-mapper
./gradlew assembleDebug
```

The first build downloads ~400 MB of dependencies. If `network.access` is off in your
Claude Code workspace you will need to run this locally.

### Known issues to fix before first build

1. **Missing `@AndroidEntryPoint` on `OverlayEditorService`** – the floating-window
   service stub in `:service` does not yet have a Hilt entry point; add it or inject
   manually with `EntryPoints`.
2. **`compose-material3-window-size` import** in `TitanNavHost.kt` — verify the catalog
   alias matches `libs.compose.material3.window.size` (dot-separated in Kotlin DSL).
3. **`ProfilesRoute` / `DashboardRoute` signatures** — confirm parameter lists match what
   `TitanNavHost.kt` calls (no extra required params).
4. **ProGuard** — the release build may need additional keep rules for kotlinx.serialization
   sealed interfaces; test with `assembleRelease --stacktrace`.
